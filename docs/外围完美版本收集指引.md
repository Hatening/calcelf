# CalcElf 知识卡 · 外围完美版本收集指引

> 本文档教你（非技术背景负责人）如何把"统一建卡提示词"发给各大模型、如何截图权威呈现、如何整理文件夹交回给工程团队。
> 目标：每族 20–50 道"完美版本"真题 + 权威呈现参照，让知识卡的质量从"合成"升级到"真题校准"。

---

## 一、整体流程（每族重复 5 步）

```
选族 → 发提示词给模型 → 收集真题 → 截图权威呈现 → 整理文件夹 → 交回
```

每族预计耗时 30–60 分钟（熟练后更快）。

---

## 二、统一建卡提示词（直接复制粘贴）

把下面这段 + 该族的真题文档一起发给任意大模型（DeepSeek / GPT / Gemini / 千问）：

```
你是 K12 数学/科学动画引擎的资深作者。请为渲染器族「<FAMILY_ID>」产出一张可运行的知识卡。

【背景】模型在运行时不做推理、不写动画代码，只输出 {"id","params"}；
解题、校验、渲染全部由确定性函数完成。

【输入】本题型的 20-50 道真题样本（见附件）与若干权威呈现参照截图。

【请交付一个 JS 模块】
1. id / name / keywords（含同义词、常见错写）。
2. extract(problemText): 从题目抽出参数（数字+单位），给默认值、单位换算、confidence；
   抽不出返回 null。
3. solve(params): 确定性求解，返回 {answer, steps:[{narration, visualHint}]}；
   steps 必须按 CPA 顺序：具象物体→图示→抽象符号。
4. validate(params, solved): 用数值断言校验答案与结构（含"必须含至少一个图形场景"）。
5. renderParams(solved): 输出渲染器吃的确定性数据（实体表、时间轴、关键帧、颜色、布局）。
6. 设计要求：颜色语义固定；圆润友好；自动布局不重叠；所有可见文字用变量占位以便多语言；
   对象有稳定 id、全程不消失；每拍停留约 5 秒。

【纪律】
- 只输出可运行代码与简短说明，不要解释性长篇。
- 不要硬套：题目不像本族就明确返回 needFallback:true。
- 给出 3 个自测样例（含 1 个易错/边界）及期望输出。
```

> 用法：把 `<FAMILY_ID>` 替换成族名（如 `bars`、`motion`），把真题文档作为附件上传，收回的代码交给工程团队并入引擎。

## 四、如何从各大模型收集"完美版本"

### 4.1 DeepSeek（推荐主力，免费/便宜）
1. 打开 chat.deepseek.com
2. 选择"深度思考"模式（R1）
3. 粘贴统一建卡提示词 + 上传真题文档
4. 要求："请先列出 20 道该族真题，再逐题给出抽参结果和期望渲染参数"
5. 把完整回复复制保存为 `deepseek_<族名>.md`

### 4.2 GPT（GPT-4o / o1）
1. 打开 chat.openai.com
2. 上传真题文档 + 粘贴提示词
3. 要求 o1 模型做"推理验证"：对每道题验证答案正确性
4. 保存为 `gpt_<族名>.md`

### 4.3 Gemini（Google，多模态强）
1. 打开 gemini.google.com
2. 上传真题文档 + 参照截图
3. 要求："根据截图的呈现风格，给出该族的渲染参数设计"
4. 保存为 `gemini_<族名>.md`

### 4.4 千问（Qwen，中文理解好）
1. 打开 tongyi.aliyun.com
2. 粘贴提示词 + 中文真题
3. 特别适合中文应用题的语义理解
4. 保存为 `qwen_<族名>.md`

### 4.5 交叉验证（重要）
- 同一道题，至少让 2 个模型分别给出答案和抽参
- 如果两个模型答案不一致，标记为"争议题"，人工确认
- 把争议题单独存入 `disputed/` 文件夹

## 五、如何截图权威呈现参照

### 5.1 PhET 模拟（phet.colorado.edu）
1. 搜索对应模拟（如 "Number Line"、"Balance Scale"）
2. 用 HTML5 版本（不要 Java 版）
3. 截取 3 个关键画面：初始状态、中间操作、最终结果
4. 保存为 `phet_<族名>_<序号>.png`
5. 注意：只学逻辑与布局，**不直接搬素材**（PhET 是 CC/GPL 协议，需重写代码）

### 5.2 Polypad（mathigon.org/polypad）
1. 注册免费账号
2. 用 Bar Models / Number Line / Balance 工具搭建题目
3. 截图保存为 `polypad_<族名>_<序号>.png`

### 5.3 Desmos（desmos.com/calculator）
1. 输入函数表达式
2. 调整窗口到合适范围
3. 截图保存为 `desmos_<族名>_<序号>.png`

### 5.4 GeoGebra（geogebra.org）
1. 用 Geometry 或 Graphics 工具
2. 绘制图形、标注边长角度
3. 截图保存为 `geogebra_<族名>_<序号>.png`

### 5.5 洋葱学院（yangcong345.com）
1. 搜索对应知识点视频
2. 暂停在动画关键帧
3. 截图保存为 `onion_<族名>_<序号>.png`
4. 注意：仅作内部参照，不对外传播

## 六、文件夹命名规范

每族一个文件夹，结构如下：

```
<族名>/
├── problems/           # 真题文档
│   ├── basic.md        # 基础题（10-15道）
│   ├── medium.md       # 中等题（8-12道）
│   └── hard.md         # 易错/边界题（3-5道）
├── model_outputs/      # 各模型产出
│   ├── deepseek.md
│   ├── gpt.md
│   ├── gemini.md
│   └── qwen.md
├── references/         # 权威呈现截图
│   ├── phet_1.png
│   ├── polypad_1.png
│   └── ...
├── disputed/           # 争议题（答案不一致的）
│   └── question_03.md
└── README.md           # 该族总结：题目数量、模型一致性、特殊注意点
```

### 真题文档格式（每题一行或一段）
```
## 第1题
题目：一只青蛙在10米深的井底，白天爬3米，晚上滑2米，几天爬出？
答案：8天
易错点：最后一天爬出后不会再滑下来
来源：人教版三年级下册
```

## 七、交回给工程团队

1. 把整个 `<族名>/` 文件夹打包为 zip
2. 命名：`kard_<族名>_v1_YYYYMMDD.zip`
3. 上传到项目共享目录或发给工程负责人
4. 工程团队会：
   - 把真题合并入 `samples/<族名>.json` 黄金集
   - 用参照截图校准渲染器的视觉风格
   - 用模型产出交叉验证知识卡的 extract/solve
   - 跑无头回测，通过率≥90% 才上线

## 九、常见问题

**Q：模型给出的代码能直接用吗？**
A：不能。模型产出作为"草稿"，工程团队会统一重构、并入引擎、跑回测。你只需要保证题目和答案的质量。

**Q：题目从哪里来？**
A：课本（人教版/北师大版/苏教版）、教辅（5·3、黄冈）、在线题库（菁优网、作业帮）。注意不要直接复制有版权的整页内容，用自己的话复述题目。

**Q：截图会侵权吗？**
A：仅作内部参照、不对外发布、重写代码不搬素材，属于合理使用范围。不要把截图直接放进产品。

**Q：一个族要多少题才够？**
A：P0 八族每族 20–50 道。基础题覆盖常见变体，易错题专门针对学生常犯错误。题不在多，在于覆盖变体全。
